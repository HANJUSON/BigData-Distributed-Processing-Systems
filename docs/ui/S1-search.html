서랍: / 또는 버튼으로 열고 Esc·배경으로 닫음

주석

  1. 1조건 패널(왼쪽 고정, 280 px). 조건을 바꾸면 300 ms 디바운스 후 자동 검색. ‘검색’ 버튼 없음. 결과 영역만 다시 그리고 패널의 스크롤·포커스 유지. /로 첫 입력에 포커스.
  2. 2거리: 이중 슬라이더 + 숫자 입력, 0–80 m, 5 m 단위. 최솟값 > 최댓값이면 입력 칸 바로 아래 “최솟값이 최댓값보다 큽니다”, 검색 보류.
  3. 3결과 수 ‘장면 N개 · 객체 M개’ — 검색 의미가 “한 객체가 모든 조건을 만족”이므로 둘 다 표시(aria-live).
  4. 4정렬: 일치 객체 많은 순(기본) · 거리 먼 순 · 포인트 적은 순 · 장면 번호 순.
  5. 5적용 조건 칩, × 로 하나씩 해제. 조건 없으면 ‘전체 장면 · 조건 없음’.
  6. 6결과 카드: 썸네일(박스를 미리 그린 WebP, 폭 320 px, lazy) · frame_id · 일치 객체 수 · 최근접 거리 · 관측 부족/검수 배지. 24개/페이지, 1–4열.
  7. 7모든 조건·정렬·페이지를 URL에: /?cls=Pedestrian&dmin=30&dmax=80&occ=1&page=2
초기
전체 장면, 일치 객체 많은 순으로 바로 결과 표시.
로딩
카드 모양 스켈레톤, 300 ms 이내면 표시 안 함.
빈 결과
“조건에 맞는 장면이 없습니다. 거리 조건을 해제하면 312개가 있습니다.” + 추천 프리셋. 완화 수는 MySQL 프로시저가 계산.
오류
“데이터베이스에 연결하지 못했습니다…” + 자세히 + 다시 시도.
부분 성공
썸네일 누락 카드만 자리표시로.
