# 사용성 점검 (U-13) — 진행 양식

> **이 문서는 채워 넣을 양식입니다.** 점검은 아직 하지 않았습니다. 참여자를 모아 직접 진행하고, 4절·6절 표와 7절 요약을 채워 주세요. 기준은 README 9.11 "사용성 점검(U-13)"입니다.

## 1. 목표와 판정 기준

README 9.11: 프로젝트를 모르는 사람 3–5명에게 **설명 없이** 9.2의 과업 T1–T3을 맡기고, 성공 여부·걸린 시간·막힌 지점을 기록합니다.

| 기준 | 목표 |
| --- | --- |
| 과업 성공률 | 90% 이상 (전체 시도 중 "성공" 비율) |
| 과업당 걸린 시간 | 중앙값 3분 이내 |
| 출시 차단 문제 | 두 명 이상이 **같은 곳**에서 막히면 출시 차단으로 보고 발표(12/8) 전에 수정 |

일정: README 8절에 따라 11/30–12/8에 점검과 수정을 합니다.

## 2. 참여자

- 인원: 3–5명
- 포함: 이 프로젝트와 웹 앱을 본 적이 없는 사람. 브라우저 사용에 익숙한 사람.
- 제외: 이 프로젝트의 개발·설계·리뷰에 참여한 사람, 와이어프레임이나 화면 캡처를 미리 본 사람.
- 가능하면 섞기: 자율주행·컴퓨터비전을 아는 사람 1명 이상과 모르는 사람 1명 이상. 키보드만 쓰는 참여자가 있으면 따로 표시합니다.
- 참여자는 P1, P2 … 로만 기록하고 이름은 적지 않습니다.

## 3. 준비

1. MySQL을 켜고 웹 앱을 실데이터로 실행합니다(`KITTI_DEMO` 끔). 방법은 [RUNBOOK.md](RUNBOOK.md) 9·11절.
   ```bash
   sudo systemctl start mysql
   flask --app webapp run --port 5050
   ```
2. 브라우저 창 1440×900(README 9.8 기준 화면), 첫 화면 `http://127.0.0.1:5050/`. 참여자마다 새 시크릿 창으로 시작해 이전 검색·테마 기록이 남지 않게 합니다.
3. 성능 측정(`kitti.bench`)과 동시에 하지 않습니다.
4. 진행자 1명(과업 안내·시간 재기), 기록자 1명(관찰 기록). 한 사람이 둘 다 해도 됩니다.
5. 화면 녹화는 참여자가 동의한 경우에만 합니다.

## 4. 진행 절차

1. 동의를 받습니다(5절).
2. 안내 문구를 그대로 읽습니다: "이 화면을 처음 보는 사람이 원하는 장면을 찾을 수 있는지 확인하려고 합니다. 시험하는 대상은 화면이지 여러분이 아닙니다. 생각나는 것을 소리 내어 말해 주세요. 진행하는 동안 저는 도와드리지 않습니다."
3. 과업 카드를 한 장씩 건네고, 참여자가 읽고 "시작"이라고 말하면 시간을 잽니다.
4. 참여자가 "끝"이라고 말하거나, 5분이 지나거나, 포기하면 멈춥니다.
5. 과업마다 바로 SEQ를 묻습니다(4.2).
6. 세 과업이 끝나면 짧게 묻습니다: "가장 헷갈린 곳은 어디였나요?", "용어 중 뜻을 몰랐던 것이 있었나요?"
7. 진행자는 설명·힌트를 주지 않습니다. 참여자가 질문하면 "지금 생각하시는 대로 해 보세요"라고만 답합니다. 힌트를 줬다면 "도움 후 성공"으로 기록합니다.

### 4.1 과업 (README 9.2 원문)

| ID | 사용자 | 과업 |
| --- | --- | --- |
| T1 | 인식 모델 평가자 | “30 m 이상, 일부 가림인 보행자가 있는 장면”을 찾아 첫 결과의 상세를 연다. |
| T2 | 데이터 검수자 | 관측 부족 객체가 있는 장면에서 해당 객체를 이미지와 BEV에서 찾아 판정을 남긴다. |
| T3 | 과목 평가자(교수·청중) | 품질 검사 결과와 Spark `local[8]`의 속도 향상 배수를 찾는다. |

**T2 주의:** 판정 저장은 DB 과목 기능이라 현재 빌드에서는 ‘판정 남기기’가 비활성입니다([RESULTS.md](RESULTS.md) 9절). DB 과목 기능이 연동되기 전에 점검한다면 성공 기준을 "관측 부족 객체를 이미지와 BEV에서 모두 짚고 ‘판정 남기기’ 버튼까지 찾음"으로 정하고, 그 사실을 7절 요약에 적습니다.

### 4.2 측정 항목

| 항목 | 기록 방법 |
| --- | --- |
| 성공 | 성공 / 도움 후 성공 / 실패(포기·5분 초과·틀린 답). 성공률 계산에는 "성공"만 셉니다. |
| 걸린 시간 | "시작"부터 "끝"까지 초 단위 |
| 오류 | 과업과 관계없는 화면으로 간 횟수, 잘못된 조건을 넣은 횟수, 되돌아간 횟수 |
| 막힌 지점 | 10초 이상 멈추거나 "어디 있지?"라고 말한 곳. 화면 이름과 요소를 적습니다(예: S1 가림 토글). |
| SEQ | 과업 직후 "이 과업은 얼마나 쉬웠나요?" 1(매우 어려움) – 7(매우 쉬움) |
